1//! Constants used throughout in [Zigner](https://github.com/rotkonetworks/zigner)
2//! and Zigner-supporting ecosystem.
3//!
4//! Zigner uses **cold** database.
5//!
6//! The database used on a non air-gapper device for updates generation is
7//! called **hot** database.
8//!
9//! Cold database is generated during the build, so it gets addressed both on
10//! active and on signer side.
11//!
12//! Cold database contains following trees:
13//!
14//! - [`SPECSTREE`], with network specs in cold database format
15//! - [`VERIFIERS`], with network verifiers, i.e. data on who user trusts to
16//!   sign updates for a given network
17//! - [`METATREE`], with network metadata
18//! - [`ADDRTREE`], with user addresses public information
19//! - [`SETTREE`], containing general verifier, types information, and Vault
20//!   danger status
21//! - [`TRANSACTION`], used to store temporarily transaction data while the
22//!   user accepts or declines it
23//! - [`HISTORY`], with history log
24//!
25//! Hot database contains following trees:
26//!
27//! - [`SPECSTREEPREP`], with network specs in hot database format
28//! - [`METATREE`], with network metadata, at most two versions for each network
29//! - [`META_HISTORY`], with block hash at which the metadata was fetched
30//! - [`ADDRESS_BOOK`], with network information needed to make RPC calls
31//! - [`SETTREE`], containing types information
32//!
33//! Common constants are:
34//!
35//! - tree names in cold database alone or shared between cold and hot databases
36//! - key names in [`SPECSTREE`] tree of cold database alone or shared between
37//!   cold and hot databases
38//! - recurring throughout the Vault seed phrase for Alice
39//! - QR graphic settings, used for both static and animated PNG QR codes
40//!
41//! # Features
42//! Feature `"signer"` corresponds to everything related exclusively to Vault
43//! air-gapped device. It includes:
44//!
45//! - keys for [`TRANSACTION`] tree, used for temporary storage for various
46//!   kinds of transactions while they are shown to user for approval
47//! - display settings for history log and word guesser
48//!
49//! Feature `"active"` corresponds to all Vault-related things happening
50//! exclusively **without** air-gap. It includes:
51//!
52//! - default database addresses for hot database and cold release database
53//! - hot database specific tree names
54//! - default color settings for network specs
55//! - default files and folders name fragments, for use with `generate_message`
56//! - fountain qr generation parameters (large apng fountain qr codes are
57//!   generated only on the hot side)
58//!
59//! Feature `"test"` includes all `"signer"` and `"active"` contents, and some
60//! recurring data for integration testing, such as known identicons and known
61//! export QR codes.

102/// Tree name for the tree storing fingerprints of consumed FROST signing
103/// nonces. Persisting these across app restarts is critical: an attacker

106/// FROST private key. Key: SHA-256(nonces_hex) (32 bytes). Value: 8-byte
107/// little-endian unix timestamp.
